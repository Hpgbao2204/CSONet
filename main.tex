\begin{abstract}
Proxy upgrades retain an address and persistent storage while replacing the code that interprets them.  A new implementation may therefore reinterpret old bytes or change the observable transition of a preserved entry point.  We present \tool, an offline analyzer combining compiler-grounded storage footprints with selective relational verification.  Its product obligation compares success status, return or revert data, events, external interactions, and related post-state.  Satisfiable obligations yield replayable counterexamples; unsatisfiable obligations establish equivalence within the encoded semantics, declared domain, and supported frontend fragment; unsupported constructs remain explicit.  We evaluate 180 compiling Solidity upgrade pairs over 20 originals and 37 mutation operators using OpenZeppelin and differential-fuzzing baselines, Anvil replay, and 43,500 repeated timing observations.  Storage analysis obtains precision 0.885 and recall 0.900, while behavioral analysis obtains precision 0.873 and recall 0.800.  All 48 solver counterexamples replay on Anvil, with a two-sided Wilson 95\% lower endpoint of 0.926.

\keywords{Upgradeable smart contracts \and Relational verification \and Storage layout \and SMT \and Solidity}
\end{abstract}

\section{Introduction}
\label{sec:introduction}

Upgradeable proxies decouple stable state from replaceable logic.  The pattern is operationally useful but weakens the usual intuition that deployed code is immutable: an administrator may redirect every subsequent delegate call while the proxy retains its old storage.  Recent empirical studies show both the prevalence and diversity of proxy mechanisms~\cite{li2024characterizing,zhang2025proxy}. EIP-1967 standardizes several administrative slots, but it does not constrain the implementation's ordinary state layout~\cite{eip1967}.  Consequently, an individually correct new version may still be an unsafe replacement.

Existing tools cover important parts of this problem.  OpenZeppelin compares compiler layouts~\cite{openzeppelin2025upgrades}; CRUSH detects storage collisions and CollisionRepair repairs them~\cite{ruaro2024crush,pan2025collisionrepair}. Recent single-version systems infer invariants, verify declarative contracts, or synthesize properties~\cite{chen2024invariants,chen2024dcv,liu2025propertygpt}; specialized analyzers target address checks and modified library guards~\cite{sun2024avverifier,liu2024zepscope}.  None of these ingredients alone states which old storage bytes a new version may reinterpret \emph{and} whether selected public transitions remain observationally equivalent.

We formulate replacement safety as a conjunction of physical layout compatibility and selective relational equivalence.  The word ``selective'' is essential: upgrades often intentionally add or change methods, so global bytecode equivalence is neither required nor desirable.  For each preserved method, \tool constructs a product formula and asks Z3~\cite{demoura2008z3} whether two related executions can be distinguished.  A model is checked by an independent concrete summary interpreter and replayed on a local EVM.

The main contribution is a selective, compiler-grounded account of upgrade safety, realized through three concrete elements:
\begin{itemize}
\item a byte-accurate compatibility relation for packed cells, dynamic roots, inheritance, reserved gaps, and literal assembly writes;
\item a product semantics over status, return or revert data, events, external interactions, and projected post-state, with explicit \(\Unknown\) and \(\Timeout\) verdicts; and
\item a controlled evaluation over 180 compiling upgrade pairs with repeated measurements, baselines, EVM replay, and component ablations.
\end{itemize}

\section{Background and Related Work}
\label{sec:related}

\subsection{Upgradeable storage}

Under \texttt{delegatecall}, implementation instructions read and write the proxy's storage.  Solidity assigns state variables according to inheritance, packing, and type-specific root rules~\cite{solidity2025layout}.  Mappings and dynamic arrays occupy a root slot whose descendants are hash-derived; moving the root therefore changes every logical cell even when the value type is unchanged.  Recent ecosystem studies characterize upgrade mechanisms and their security implications~\cite{li2024characterizing,zhang2025proxy}. CRUSH detects collisions and synthesizes exploits; CollisionRepair reconstructs slot ownership and patches affected systems~\cite{ruaro2024crush,pan2025collisionrepair}. Sorensen develops a mechanized upgrade framework in Coq~\cite{sorensen2024upgrades}.  Our focus is an executable two-version relation that joins layout preservation with selected behavioral obligations.

\subsection{Verification and testing}

Recent work illustrates three complementary directions.  DCV verifies declarative contracts by induction, invariant studies quantify which inferred properties are effective, and PropertyGPT retrieves and generates candidate specifications~\cite{chen2024dcv,chen2024invariants,liu2025propertygpt}. AVVerifier and ZepScope specialize program analysis to address validation and library-check consistency~\cite{sun2024avverifier,liu2024zepscope}, whereas CrySol combines replay and dynamic taint analysis for cryptographic defects~\cite{zhang2025crysol}.  Verification-service studies expose mismatches between published source and deployed bytecode~\cite{ma2024verification}; Osprey and iAudit respectively synthesize concrete attacks and justified audit findings~\cite{ruaro2025osprey,ma2025iaudit}.  Empirical evaluations nevertheless report substantial gaps between tool capabilities and practitioner needs~\cite{chaliasos2024tools,li2024sast}.  These systems analyze one version or one vulnerability family, while \tool asks whether two versions preserve a declared cross-version relation. \section{Relational Upgrade-Safety Model}
\label{sec:problem}

Let \(V_i=(C_i,\mathcal L_i)\) denote implementation code and compiler storage layout for version \(i\in\{1,2\}\).  A layout entry for variable \(v\) is
\begin{equation}
\begin{aligned}
\lambda_i(v)&=\bigl(s_i(v),o_i(v),w_i(v),\tau_i(v),\pi_i(v)\bigr).
\end{aligned}
\label{eq:cell}
\end{equation}
where \(s\) is a 32-byte slot, \(o\) a byte offset, \(w\) a byte width, \(\tau\) a semantic type, and \(\pi\) the declaration path induced by inheritance.  Its physical footprint is
\begin{equation}
\begin{aligned}
B_i(v)&=\{32s_i(v)+o_i(v),\ldots,\\
&\qquad 32s_i(v)+o_i(v)+w_i(v)-1\}.
\end{aligned}
\label{eq:footprint}
\end{equation}
For a mapping or dynamic array, \(B_i(v)\) denotes the root; the derived addressing function remains part of \(\tau_i(v)\).

To distinguish physical coincidence from semantic compatibility, define the byte-interpretation map \(\mu_i:\mathbb{N}\rightarrow\mathcal{T}\times\mathcal{P}\times\mathbb{N}\) by
\begin{equation}
\begin{aligned}
\mu_i(b)&=\bigl(\tau_i(v),\pi_i(v),b-\min B_i(v)\bigr),\\
&\qquad\text{for the unique }v\text{ such that }b\in B_i(v).
\end{aligned}
\label{eq:byte-interpretation}
\end{equation}
For a mapping key \(k\) and a dynamic-array index \(j\), descendant locations are generated by
\begin{equation}
\begin{aligned}
\alpha_i^{\mathrm{map}}(v,k)
&=H(\operatorname{enc}(k)\Vert\operatorname{enc}(s_i(v))),\\
\alpha_i^{\mathrm{arr}}(v,j)
&=H(\operatorname{enc}(s_i(v)))
  +\left\lfloor\frac{jw_i(v)}{32}\right\rfloor .
\end{aligned}
\label{eq:root-addressing}
\end{equation}
Equation~\eqref{eq:root-addressing} is a schematic root/slot derivation; the current frontend does not claim a complete encoding of packed dynamic descendants.  Root equality alone is therefore insufficient: the recursive type must induce the same descendant-address language.

Let \(P_1\) be the old variables whose values must persist and \(P_2\) the candidate-version declarations.  A total correspondence \(\rho:P_1\rightarrow P_2\), equivalently \(\operatorname{Dom}(\rho)=P_1\), is compatible when
\begin{equation}
\begin{aligned}
\forall v\in P_1:\quad
B_1(v)&=B_2(\rho(v)),\\
\tau_1(v)&\simeq\tau_2(\rho(v)).
\end{aligned}
\label{eq:layout-compatible}
\end{equation}
and \(\rho\) is injective.  Compatibility additionally requires \(\mu_1(b)=\mu_2(b)\) for every compiler-visible persistent byte after paths are transported by \(\rho\).  The relation \(\simeq\) requires equal recursive encoding for roots and equal signedness and width for scalar interpretation. New variables are allowed only outside \(\bigcup_{v\in P_1}B_1(v)\), except that a suffix of a declared gap may be consumed without moving its retained suffix.

For public method \(f\), we model one execution as
\begin{equation}
\begin{aligned}
\sem{f}_{i}(\sigma,a,\kappa)
&=(q_i,r_i,d_i,e_i,x_i,\sigma'_i).
\end{aligned}
\label{eq:transition}
\end{equation}
where \(\sigma\) is storage, \(a\) contains arguments and sender context, and \(\kappa\) is the ordered external-call outcome sequence (the oracle shared by the two modeled executions).  Here \(q\) is success status, \(r\) return bytes, \(d\) revert bytes, \(e\) the ordered event trace, and \(x\) the ordered external-call trace.  The observable projection is
\begin{equation}
\begin{aligned}
\obs_\rho(t_i)
&=\bigl(q_i,\ q_i?r_i:d_i,\ e_i,\ x_i,\\
&\qquad \sigma'_i\!\downarrow_{\operatorname{Dom}(\rho)}\bigr).
\end{aligned}
\label{eq:observation}
\end{equation}
Including failure payloads and interaction order prevents a weak post-state-only notion of equivalence.  Equality of the projected post-states means that every pair of cells related by \(\rho\) again has equal interpreted value, thereby re-establishing \(I_\rho\) for the next preserved call.

For each preserved method, the distinguishability set collects all related executions with unequal observations:
\begin{equation}
\begin{aligned}
\Delta_f(\rho)=\bigl\{&(\sigma_1,\sigma_2,a,\kappa)\mid
\sigma_1\sim_\rho\sigma_2,\ (a,\kappa)\in D_f,\\
&\obs_\rho(\sem{f}_1(\sigma_1,a,\kappa))
\neq\obs_\rho(\sem{f}_2(\sigma_2,a,\kappa))\bigr\}.
\end{aligned}
\label{eq:distinguishability-set}
\end{equation}
\(D_f\) is the declared verification domain for \(f\): it bounds ABI arguments, sender and initial-state assumptions, and admissible oracle outcomes in \(\kappa\).  It is part of the claim rather than an inferred description of all production calls.

\begin{definition}[Selective upgrade safety]
Given preserved methods \(M_p\) and the family \(D=\{D_f\}_{f\in M_p}\), the upgrade \(V_1\leadsto V_2\) is safe relative to \((\rho,M_p,D)\) iff
\begin{equation}
\begin{aligned}
\mathsf{Compat}_{\mathcal{L}}(\rho)\ \land\
\bigcup_{f\in M_p}\Delta_f(\rho)&=\varnothing .
\end{aligned}
\label{eq:selective-safety}
\end{equation}
where \(\mathsf{Compat}_{\mathcal{L}}\) abbreviates Eq.~\eqref{eq:layout-compatible}, injectivity, descendant-address preservation, and non-overlap with newly allocated cells.
\end{definition}

\subsection{Compiler-grounded layout relation}

The implemented full configuration first instantiates correspondence by the compiler-emitted declaration label, then checks physical position and normalized recursive type.  This deliberately conservative identity rule can reject an internal rename, a limitation isolated by the ID and S+T ablations.  For an old cell \(v\) and candidate \(u\), the compatibility predicate is
\begin{equation}
\begin{aligned}
K(v,u)={}&[s_1(v)=s_2(u)]\land[o_1(v)=o_2(u)]\\
&{}\land[w_1(v)=w_2(u)]\land[\tau_1(v)\simeq\tau_2(u)].
\end{aligned}
\label{eq:cell-compatibility}
\end{equation}
Let \(\nu_i(v)\) be the compiler label.  The prototype uses \(\rho_N(v)=u\) iff \(\nu_1(v)=\nu_2(u)\), requires \(\operatorname{Dom}(\rho_N)=P_1\), and emits a component-wise diagnostic rather than collapsing every failure into one Boolean:
\begin{equation}
\begin{aligned}
\boldsymbol{\ell}(v,u)
={}&\bigl([s_1(v)\neq s_2(u)],[o_1(v)\neq o_2(u)],\\
&[w_1(v)\neq w_2(u)],[\tau_1(v)\not\simeq\tau_2(u)]\bigr),\\
\mathsf{Compat}_{\mathcal L}(\rho_N)
\Longleftrightarrow{}&
\operatorname{Dom}(\rho_N)=P_1\\
&{}\land
\sum_{v\in\operatorname{Dom}(\rho_N)}
\|\boldsymbol{\ell}(v,\rho_N(v))\|_1=0.
\end{aligned}
\label{eq:layout-diagnostic}
\end{equation}
Missing labels are deletion diagnostics.  The checker additionally validates gap shrinkage and scans Yul/assembly for literal \texttt{sstore} destinations that overlap compiler-managed cells.  A computed destination is conservatively \(\Unknown\), because syntactic constant folding would be incomplete.

\subsection{Selective relational obligation}

An unchanged method is skipped only when its body and signature are unchanged and the modifier definitions, internal-call bodies, inheritance clauses, and contract-level dependencies are also unchanged.  For each remaining preserved method, the frontend extracts guards, writes, returns, events, calls, and effect order.  Two summaries share symbolic pre-state and arguments.  The counterexample formula is
\begin{equation}
\begin{aligned}
\Phi_f={}&I_\rho(\sigma_1,\sigma_2)\land D_f(a,\kappa)\\
&{}\land T_{1,f}(\sigma_1,a,\kappa,t_1)
\land T_{2,f}(\sigma_2,a,\kappa,t_2)\\
&{}\land\neg\bigl(\obs_\rho(t_1)=\obs_\rho(t_2)\bigr).
\end{aligned}
\label{eq:product}
\end{equation}
If \(\Phi_f\) is satisfiable, its model is a regression witness.  If unsatisfiable, the verdict is \emph{Safe within the encoded model}: the procedure establishes equivalence for the selected method within the encoded semantics, declared domain, and admitted frontend fragment.  Unsupported expressions produce \(\Unknown\); solver resource exhaustion produces \(\Timeout\).

Verdict precedence prioritizes evidence:
\begin{equation}
\begin{aligned}
\Unsafe\succ\Timeout\succ\Unknown\succ\Safe.
\end{aligned}
\label{eq:verdict}
\end{equation}
Thus a definite layout collision is not hidden by an unrelated unsupported method.  A \(\Safe\) verdict requires every reached construct to be \emph{Safe-capable}, meaning the frontend can construct its complete obligation. The admitted fragment covers the corpus arithmetic, guards, direct writes, returns, events, and value calls; conditional effects, loops, exceptional control flow, arbitrary revert-data encoding, behavioral inline assembly, unmodeled call kinds, lifecycle effects, and unresolved expressions propagate \(\Unknown\), never \(\Safe\).  The artifact records the construct-level admission matrix.

\subsection{Counterexample checking}

A solver model \(m\) is accepted only if a separately implemented concrete summary evaluator reproduces the observation difference.  The artifact then deploys both compiled versions on Anvil, initializes equal logical state using \texttt{anvil\_setStorageAt}, invokes the changed method, and compares call status/data, receipt status, logs, storage, and filtered opcode traces.  Replay uses batches of four fresh chains to bound provider state and isolate failures.

Figure~\ref{fig:example} illustrates why upgrade safety cannot be reduced to either layout equality or equal post-state on common successful inputs.  Let \(s_i\) be the compiler-reported root of \texttt{accounts}.  Let \(\delta_i\) denote the compiler-derived field location within the mapping value, including its slot and byte offset.  For address \(x\), the persistent cell is \(\alpha_i(x)=H(\operatorname{enc}(x)\Vert\operatorname{enc}(s_i))+\delta_i\); L1--L3 imply \((s_1,\delta_1,\tau_1)\neq(s_2,\delta_2,\tau_2)\).  Independently, choose the relational pre-state
\begin{equation}
\begin{aligned}
a.\mathit{credit}&=\mathit{amount}>0,&
\mathit{total}&\geq\mathit{amount},\\
a.\mathit{nonce}&=n=\mathit{expected},&
\neg a.\mathit{frozen},\quad
\mathit{treasury}&\neq\mathit{msg.sender}.
\end{aligned}
\label{eq:listing-witness}
\end{equation}
The old transition pays \(\mathit{msg.sender}\), increments the nonce to \(n+1\), and emits \((\mathit{amount},n+1)\); the candidate pays \(\mathit{treasury}\), leaves the nonce at \(n\), and emits \((\mathit{total}-\mathit{amount},n)\).  Thus Eq.~\eqref{eq:listing-witness} instantiates \(\Delta_{\mathrm{withdraw}}(\rho)\), while the root mismatch independently falsifies \(\mathsf{Compat}_{\mathcal L}(\rho)\).  The example therefore demonstrates both conjuncts of Eq.~\eqref{eq:selective-safety}, not merely a syntactic diff.

\subsection{Conditional guarantee and complexity}

\begin{theorem}
\label{thm:trace}
Assume Eq.~\eqref{eq:layout-compatible}, exact transition encodings \(T_{i,f}\), a modeled non-reentrant environment, preservation of the related post-state \(I_\rho\), and \(\Phi_f\) unsatisfiable for every \(f\in M_p\).  Any finite client trace containing only calls in \(M_p\), with contexts in \(D_f\), has equal observations under \(V_1\) and \(V_2\).
\end{theorem}

\begin{proof}
By induction on trace length.  Initially the stores satisfy \(I_\rho\). For the inductive step, unsatisfiability of Eq.~\eqref{eq:product} excludes an observable difference for the next call and establishes related projected post-state.  This post-state is the induction hypothesis for the remaining trace.  The result follows for every finite length.
\end{proof}

The theorem is a conditional trace-preservation result, not a mechanized frontend-to-EVM correspondence proof; its assumptions make the boundary of a positive verdict explicit.

For \(n\) layout cells, \(d\) changed preserved functions, and formula construction sizes \(g_f\), layout indexing costs \(O(n\log n)\), frontend work costs \(O(\sum_{f=1}^{d}g_f)\), and SMT solving remains theory-dependent.  Skipping unchanged methods makes \(d\), rather than the total public-method count, the dominant number of obligations.

\section{Experimental Evaluation}

\subsection{Evaluation Setup}
\label{subsec:eval-design}

RQ2 measures behavioral-regression detection relative to a 128-trial deterministic differential baseline. RQ3 isolates the contribution of layout reasoning, behavioral reasoning, type interpretation, witness validation, selective obligation construction. RQ4 measures verification cost as relational obligations plus symbolic-path mass increase.

We generate 20 original contracts across ten application families, split evenly between Transparent and UUPS proxy metadata. Each original contains 7--8 public or external functions and eight compiler-visible storage variables, covering inheritance, packed scalars, one mapping, and one dynamic array or reserved gap. |\mathcal{D}_{\mathrm{safe}}| &= |\mathcal{D}_{\mathrm{layout}}| = |\mathcal{D}_{\mathrm{behavior}}| = 60.
\end{aligned}
\label{eq:dataset-partition}
\end{equation}

Table~\ref{tab:dataset} reports the corpus composition. Per-operator counts and realization manifests are provided in the artifact; every generated pair passes compilation.

Ground truth is established by a mutation-realization validator over source and compiler artifacts that never invokes \tool; incomplete artifacts, unrealized mutations, and duplicate hashes are rejected.  The controlled construction targets causal isolation and exact cross-version labels rather than ecosystem-prevalence estimation: mined upgrades improve ecological validity but seldom expose exact behavioral ground truth.  Transparent and UUPS conventions, compiler artifacts, OpenZeppelin checks, and Anvil replay provide production-toolchain grounding without making the corpus production-representative.

Baselines are selected by task alignment. OpenZeppelin Upgrades Core is run on every safe/storage pair as the deployable layout baseline; DifferentialFuzz-128 performs 128 deterministic trials on every safe/behavior pair as the bounded observational baseline. Related single-version or vulnerability-specific systems are therefore compared qualitatively rather than treated as interchangeable executables.  On unsafe pairs, \(\Unknown\) or \(\Timeout\) counts as a false negative; on safe pairs, \(\Unsafe\) counts as a false positive. Raw accuracy treats non-decisions as incorrect, coverage counts definite \(\Safe/\Unsafe\) verdicts, and decided-case accuracy conditions on them.

Detection proportions use two-sided Wilson 95\% intervals, and paired baseline comparisons use exact McNemar tests over matching \texttt{pair\_id}s. To preserve dependence among the nine variants derived from each source, overall metrics also use a nonparametric cluster bootstrap over the 20 original contracts (50,000 replicates, seed 26072026). The full four-state confusion matrix and construct-level support matrix are provided in the artifact.

The 180 unique pairs determine detection metrics; repeated runs support timing estimates only. After three warmups, the full configuration and seven ablations are measured 30 times, and the scaling study adds 300 batch observations, yielding 43,500 timing observations. Experiments use Windows 11, an AMD Ryzen 7 7840HS (8 cores/16 threads), 32\,GB RAM, Python 3.12.10, Z3 4.13.4, Node 22.13.0, and Anvil 1.7.1. The anonymous artifact contains source pairs, manifests, measurements, replay traces, and plotting scripts; latency may vary across hardware and tool versions~\footnote{\url{https://anonymous.4open.science/r/CSONet-34CB/}}.

\subsection{Storage-Regression Detection}
\label{subsec:storage-results}

Figure~\ref{fig:storage-results} summarizes RQ1. \tool detects 54 of 60 storage regressions (90.0\%, two-sided Wilson 95\% CI: 79.9\%--95.3\%), compared with 42 of 60 for OpenZeppelin (70.0\%, 57.5\%--80.1\%). At pair level, both detect 42 cases, 12 are detected only by \tool, none only by OpenZeppelin, and six by neither; the difference is significant under exact McNemar (\(p=4.88\times10^{-4}\)) and contract-level sign-flip (\(p=0.0078\)) tests. Precision is 0.885 and \(F_1=0.893\). The family breakdown in Fig.~\ref{fig:storage-family} shows that the gain is not isolated to one operator. Figure~\ref{fig:storage-evidence} separates the compiler, assembly, unresolved, and false-alarm evidence behind the aggregate verdicts.

Six computed \texttt{sstore} destinations remain \(\Unknown\) because their target slots cannot be resolved by the current frontend. The precision loss primarily comes from label-based correspondence on safe alpha-renaming cases. This exposes a trade-off: declaration identity avoids unsafe type matches, while user-confirmable correspondence could recover safe refactoring without weakening physical checks. Figure~\ref{fig:storage-latency} shows that simplified matchers reduce latency by discarding evidence rather than optimizing the complete relation.

\subsection{Scalability under Relational Workloads}
\label{subsec:scalability-results}

Figure~\ref{fig:scalability} summarizes controlled relational batches. Figure~\ref{fig:scalability-obligations} shows median latency rising from 19.63\,ms for one obligation to 155.46\,ms for ten, with an OLS slope of 16.45\,ms and \(R^2=0.724\). Figure~\ref{fig:scalability-paths} gives \(R^2=0.767\), making aggregate symbolic-path mass the stronger tested workload proxy. For observation \(i\), the centered models are
\begin{equation}
\begin{aligned}
T_i-\bar T &= \beta_o(o_i-\bar o)+\varepsilon_i^{(o)},\\
T_i-\bar T &= \beta_p(p_i-\bar p)+\varepsilon_i^{(p)}.
\end{aligned}
\label{eq:scaling-model}
\end{equation}
where \(o_i\) denotes relational obligations, while \(p_i\) denotes aggregate symbolic paths. The measured medians plus fitted trends exhibit monotone growth with an approximately linear central trend across batches one through ten.

\section{Discussion}
\label{sec:discussion}

Ablations support the central premise of \tool: layout and behavioral reasoning provide complementary evidence. Layout analysis exposes structural reinterpretation; relational obligations capture guards, recipients, events, and interaction order. Neither component attains the combined coverage.

Selectivity improves decision coverage as well as runtime: analyzing every public function exposes unrelated unsupported constructs without improving detection. Preserved-method obligations match upgrade practice, where new functionality may coexist with stable legacy transitions.

The three evidence levels serve different roles. Compiler diagnostics identify the slot, offset, width, and type relation behind a structural conflict; SMT models expose distinguishing symbolic conditions; Anvil confirms them over compiled bytecode, results, logs, storage, and opcode traces. Reproduction of all 48 witnesses shows that unsafe verdicts are operational rather than solver-only artifacts. Replay validates counterexamples, not frontend completeness or an unsatisfiable result.

Conservative verdicts trade completeness for trust: label identity creates seven false alarms on safe renames; computed assembly and unsupported behavior remain \(\Unknown\). User-confirmed correspondence and control-flow-sensitive summaries are direct extension points.

The corpus is designed for controlled identification, not production prevalence. Exact mutation labels and a non-\tool\ realization validator strengthen internal validity; shared originals limit pair independence, addressed by contract-cluster bootstrap. Compiler, proxy, OpenZeppelin, and Anvil components provide production-toolchain grounding, but not production representativeness. The results therefore establish controlled effectiveness over the declared transformation vocabulary; production-wide recall remains outside the present claim.

\section{Conclusion}
\label{sec:conclusion}

\tool frames Solidity proxy replacement safety as selective relational verification of persistent-state interpretation and observable transitions. Across 180 compiling upgrade pairs, it detects 54 of 60 storage regressions, a significant 20-point gain over OpenZeppelin on the paired corpus, and 48 of 60 behavioral regressions versus 44 under deterministic differential execution. All 48 solver witnesses reproduce on Anvil. Compiler-grounded storage reasoning, selective product obligations, explicit uncertainty, and independently checked counterexamples therefore provide stronger controlled upgrade evidence than layout checking or bounded differential execution alone.

The guarantee remains bounded by the declared domain, admitted frontend fragment, and modeled environment. Computed assembly, control-flow-sensitive effects, conservative rename correspondence, and independently collected production histories remain open. Future work will broaden these boundaries while preserving the separation between bounded safety, replayable unsafety, and explicit uncertainty.
